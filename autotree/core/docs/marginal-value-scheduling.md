# Marginal-value scheduling (priced branches)

The Tree-KV engine supports `policy="emvpt"` for marginal-value scheduling during
generation. EMVPT uses the existing beam scheduler for branch creation and shared
token-budget accounting, then adds a value-based pruning pass in the engine. The
policy is off unless it is selected explicitly, so `beam`, `best_first`, and
`mcts` retain their existing behavior.

Each live branch maintains two incremental counters from the point where that
branch is created:

- the sum of its sampled output-token log probabilities;
- the number of output tokens generated by that branch.

The value proxy is their running mean in natural-log-probability units per token.
It uses log probabilities already produced during sampling and makes no extra
model calls.

Every `value_check_interval` branch tokens, the engine compares eligible live
siblings. Let `best` be the highest running mean and `mean_b` be branch `b`'s
running mean. Branch `b` is pruned when all of the following hold:

```text
best - mean_b > value_margin
branch_tokens_b >= value_warmup_tokens
live_branches > value_min_keep
```

The defaults are:

| Setting | Default |
|---|---:|
| `value_check_interval` | 16 tokens |
| `value_margin` | 0.35 nats per token |
| `value_min_keep` | 2 branches |
| `value_warmup_tokens` | 8 tokens |

The comparison uses a strict greater-than margin. When several branches qualify,
the largest value gaps are pruned first without reducing the live tree below
`value_min_keep`. A pruned branch releases its Tree-KV pages immediately. Because
the request budget is shared and counts only sampled tokens, tokens not spent on
that branch remain available to surviving branches.

The tree summary reports `value_estimates` for every branch and
`pruned_at_tokens` for EMVPT requests. `pruned_at_tokens` is the number of tokens
the branch generated when it was pruned, or `null` for branches not pruned by the
value rule. These fields are omitted for other policies.

EMVPT acts only during generation. Final winner selection is unchanged. In
particular, `scorer="self_consistency"` still extracts answers and applies the
majority vote among branches that survive to finalization.

## Caveat

Mean sampled-token log probability is a practical proxy, not a trained estimate
of downstream task value. It can favor locally likely text and can mis-rank
branches whose useful reasoning initially has lower probability. The proxy is a
stand-in until a trained value head is available, and the margin, interval, and
warmup should be treated as workload-dependent controls rather than universal
quality guarantees.
